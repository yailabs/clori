# Getting help with YVEX

Start with the [quick start](README.md#quick-start) and
[operator runbook](docs/operator-runbook.md). The
[documentation map](docs/README.md) links the current contracts, supported
model boundaries, and development guides. [ROADMAP.md](ROADMAP.md) records
release status and open qualification gates.

For a reproducible defect, search the
[existing issues](https://github.com/yailabs/yvex/issues) and then use the
[bug report form](https://github.com/yailabs/yvex/issues/new?template=bug_report.yml).
Include the exact commit, command, expected and observed behavior, and relevant
compiler, OS, and backend details. Use small synthetic inputs and sanitized
logs. Internal ownership knowledge and a large model download are not
prerequisites for reporting a bug.

Use [CONTRIBUTING.md](CONTRIBUTING.md) and the engineering-change issue form
for implementation proposals. Maintainers may ask for a bounded reproduction
or clarify that a model or behavior is not yet supported; there is no
guaranteed support response time.

Report vulnerabilities privately using [SECURITY.md](SECURITY.md). Never put
credentials, private prompts or responses, personal information, model
payloads, or raw runtime dumps in a public issue.
