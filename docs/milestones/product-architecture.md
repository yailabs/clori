# Verified Execution-Substrate Refoundation

Status: accepted implementation-boundary contract

Milestone: `V010.PRODUCT.ARCHITECTURE.REFOUNDATION.0`

This contract separates execution identity, evidence depth and physical
mechanism while preserving the accepted DeepSeek-V4-Flash-DSpark product path.
Live state and dependency order belong only to [`ROADMAP.md`](../../ROADMAP.md).

## Required architecture

The implementation owns explicit product levels from verified source through
logical model, Transformation IR, physical variant, Physical Execution IR,
artifact, admission, materialization, runtime binding, immutable runtime model,
compiled execution profile, mutable session, request transaction, workload
profile, evidence and eventual release qualification.

Normal generation consumes one compiled execution profile containing an
explicit hardware profile, workload, target/draft mode, context capacity,
evidence profile and portable or device-native execution class. Production,
audit and forensic evidence are distinct; production cannot require full-array
host scans or digests solely for observation.

Generic materialization consumes terminal roles and physical decisions. It
cannot import a concrete family, register one, recover semantics from tensor
names or enter source/compiler owners. DeepSeek's model, graph and fused CUDA
projections remain three distinct family owners; the common runtime has no
family implementation directory.

Target verification produces prefix-addressable candidate state. Any admitted
prefix is promoted atomically across attention state, draft state, RNG, token
ledger, decoder, transcript and publication without replaying accepted target
tokens. SWA history uses ring semantics. Correction or bonus work is one
separate target-authored extension when the official algorithm requires it.

CUDA execution selects an identity-bound shape before mutation. The registry
distinguishes target prefill/decode, draft, verification widths, correction and
context bands, and returns exact capacity-refusal facts. Typed device views
make host materialization explicit; production greedy selection does not need
a full-vocabulary host copy. Width-N MoE and output-head contracts exist even
where the first implementation remains a portable row-local reference.

Protocol and server sessions carry an exact partial-turn contract. An
incomplete committed turn is visibly partial and refuses continuation until
reset. Human watch groups typed lifecycle events; machine trace remains JSONL.
The REPL incrementally renders UTF-8 and Markdown without mutating canonical
bytes. Explicit reasoning is available only through the source-authored typed
channel and never by substring inference.

## Acceptance evidence

Closure requires deterministic positive and refusal tests for execution
profiles, Physical Execution IR, shape selection, device views, arbitrary
accepted-prefix promotion, correction, rollback, partial sessions, protocol
roundtrip/refusal, renderer fragmentation and reasoning policy. Existing
target-only, DSpark, session, cancellation, reset, native protocol, REPL and
OpenAI paths must remain operational.

The historical capacity-failure class must be prevented by shape preflight;
accepted-token replay must be zero in production telemetry. Full repository,
no-`nvcc`, sanitizer and CUDA validation must pass before one controlled daemon
deployment. The final target table must make later GB10 work measurable without
promoting any target into a benchmark claim.

## Non-claims

This boundary does not establish final SM121 kernels, Tensor Core lowering,
native FP4 execution, optimized attention/MoE/output head, CUDA Graph
performance, continuous batching, target throughput, DSpark acceleration,
model evaluation, a release benchmark or release qualification.
