# v0.1.0 Readiness Contract

Status: unreleased target record

Authority: version-specific target, scope, required release path, and explicit
non-claims. [`ROADMAP.md`](../../ROADMAP.md) alone owns current gate states.
[Release Doctrine](doctrine.md) owns the meaning of those gates.

## Target

v0.1.0 targets identity-bound DeepSeek-V4-Flash-DSpark text generation on
NVIDIA DGX Spark / GB10 CUDA from a complete YVEX-produced GGUF artifact.

| Fact | Required value |
| --- | --- |
| Model target | `deepseek4-v4-flash-dspark` |
| Source family | DeepSeek-V4-Flash-DSpark checkpoint in the DeepSeek V4 family |
| Product executables | `yvex` |
| Hosted process | one persistent foreground `yvex server` host with an explicitly loaded DeepSeek engine generation |
| Application profile | bounded local `yvex.openai.compat.v2` |
| Local protocol | private v15 |
| Release backend | admitted GB10 CUDA profile, with exact physical variant selected only after evaluation and benchmark |

The external source location is operator configuration, not release identity.
The pinned source revision and architecture facts are recorded in the
[DeepSeek technical record](../model-families/deepseek-v4-flash.md).

## Required generation path

Release generation uses one exact chain:

```text
prompt text
-> admitted tokenizer and prompt template
-> exact prefix reuse and suffix prefill
-> family-correct Transformer, MoE, and persistent state
-> final norm and complete-vocabulary logits
-> target-only sampling or DSpark proposal plus complete-target verification
-> target-authored accepted-prefix commit
-> EOS/stop classification
-> incremental detokenized text
-> committed native and application streaming
```

The chain must use the same artifact, package binding, deployment
specialization, engine generation, session, CPU/CUDA owners, and operator path
qualified by the release. Fixture tokens, synthetic logits, selected
components, external engines, or trace output cannot substitute for it.

## Current readiness boundary

The source-to-text path, local hosted lifecycle, exact multi-turn sessions,
target-only and target-verified DSpark generation, canonical command
architecture, private protocol v16, persistent zero-engine host, dynamic engine
load/unload, and bounded OpenAI compatibility exist.
Startup optimization and bounded execution profiling are accepted. The DSpark
bootstrap is a correctness baseline; warm GB10 performance remains
optimization debt.

Model behavior/quality evaluation, the release-path full-model benchmark, and
release qualification remain open. No physical variant is selected as the
release profile until those owners accept it.

## Required closure

v0.1.0 requires all gates defined by [Release Doctrine](doctrine.md), including:

- exact source, architecture, transformation, physical-policy, artifact, and
  runtime-binding identities;
- complete artifact integrity, materialization, runtime lifecycle, and cleanup;
- CPU/CUDA conformance and fail-closed behavior;
- repeated generation, cancellation, partial-progress, reset, and reuse proof;
- behavior and quality evaluation over the hosted path;
- reproducible full-model latency, throughput, memory, and reliability
  benchmark evidence;
- canonical package/operator validation and claim audit;
- clean versioned release record and tag.

## Explicit non-claims

The unreleased v0.1 line does not currently claim:

- a supported or release-qualified DeepSeek artifact;
- model behavior or quality evaluation;
- a release-grade full-model benchmark;
- public/remote serving, authentication, TLS, or remote security;
- complete OpenAI API or another provider compatibility surface;
- global ready-sequence continuous batching, automatic resource-driven engine
  swap, distributed serving, or restart-persistent sessions;
- complete device residency, CUDA sampling, or CUDA tokenizer execution;
- optimized DSpark execution or production load-aware confidence scheduling;
- Qwen, Gemma, or another complete model-family vertical;
- release readiness.

The current truth and next dependency are intentionally not repeated here;
consult [`ROADMAP.md`](../../ROADMAP.md).
