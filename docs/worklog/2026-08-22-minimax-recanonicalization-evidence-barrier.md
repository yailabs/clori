## Before

The recanonicalized MiniMax branch had current main as an ancestor and canonical QA evidence
`1bc24b01a62e84c5ce13e186be35f59ccd10b94d5217d1b19f3df4dbae9ae42b`. That run recorded 102
`PASS`, eight `BLOCKED`, and no `FAIL`, `SKIP`, or `ERROR`. The blocked rows were external live or
performance lanes rather than evidence that their numerical contracts passed.

The eight rows were `live.deepseek.generation`, `live.minimax.audio`, `live.minimax.latent`,
`live.minimax.omni-transformer-artifact`, `live.minimax.text`, `live.minimax.tokenizer`,
`live.minimax.video`, and `performance.runtime`. The first seven represent correctness or
conformance needed by the combined-tree promotion boundary. The performance row is not required
for a correctness-only integration and may remain honestly blocked without a benchmark root.

The retained Omni bundle predated source-precision repair
`9b2b5970648c6ae99c81a3d2b066ad508f3982d2`; it was therefore not a valid post-repair oracle.
The canonical Make target also still expected the earlier three-row fixture filenames, so pointing
QA at a current request-shaped bundle produced a process-exit failure before numerical execution.

## Problem

Promotion required independent post-repair proof for the 50-block MiniMax Transformer and latent
trajectory. Enabling the actual external assets exposed two separate defects. The QA adapter could
not consume the current source-layout fixture, and the production RMS kernel narrowed the unit-
normalized activation to BF16 before multiplying by the learned weight. The source operation keeps
both operations in F32 and narrows the final affine result once.

Even after correcting that concrete source mismatch, the complete 50-block execution remained
outside the independent oracle contract. This converted the most important row from an unknown
external `BLOCKED` state into a measured numerical `FAIL`; it cannot support promotion.

## Causal analysis

The post-repair oracle is generated by the independent manual PyTorch envelope whose script has
SHA-256 `2766dca7007e320c0aa20a033d1833abbaa6786e342961c280837e50f5a10fa9`. The identity-bound
50-block, 466-row bundle manifest has SHA-256
`4c1e4d15f13e330999950239c1ffe499ecd777b1f0d1e8b99428aea23a5a2dcf`. Repeated oracle
generation was byte-identical. Its source layout contains 37 video rows, 414 audio rows, 15 text
rows, two timestep values, and all packed indices and positions.

An independent RMS comparison confirmed that the old two-round implementation changed large
populations of BF16 results relative to the source operation. Removing the intermediate narrowing
reduced first-block relative L2 error from approximately `0.00475` to `0.00176`. The same comparison
still grows through the stack: approximately `0.00398` at block 10, `0.0105` at block 30,
`0.0977` at block 40, and `0.300` at block 50 in one checkpointed run.

Complete executions agree through the early checkpoints but develop small run-to-run drift by
block 10 and amplify it later. CUDA initcheck reported zero uninitialized-access errors for the
bounded block-one execution. Disabling cuBLAS atomics, changing RMS launch width, and adding an
extra host synchronization did not establish the missing contract and were not retained. The
remaining cause is narrower than general source intake but is not yet localized to one accepted
operation.

## Decision

Match source RMS semantics in the existing generic CUDA Transformer owner: accumulate and apply
the RMS inverse and affine weight in F32, then publish one BF16 result. Keep the independent
source-shaped oracle authoritative and expose both video and audio discrepancies through canonical
QA.

Do not weaken tolerances, use YVEX output as its own oracle, reuse the stale latent bundle, or
promote a component because the early checkpoints improved. Do not begin prepared-DiT caching,
decoder caching, SSD/two-slot streaming, quantization, or performance work while the required
numerical boundary remains false.

## Implementation

The CUDA RMS kernel now performs one source-faithful BF16 publication after the affine multiply.
The focused CUDA qtype test independently calculates that policy and rejects restoration of the
intermediate narrowing.

The MiniMax text live runner was migrated to the current component ABI so the accepted external
reference remains runnable after recanonicalization. The graph-bound Transformer QA target now
consumes a request-shaped fixture with explicit row, block, and timestep geometry. Its live test
evaluates and reports both output modalities even when the first already fails.

No production owner, public ABI, Physical Execution IR, runtime binding, local protocol, artifact
identity, or model topology changed.

## After

`live.minimax.text` passes against independent reference evidence under canonical QA. The direct
layer-zero and complete 50-layer text paths also pass their existing tolerances. Bounded live
DeepSeek generation passes on the combined tree using its retained authenticated artifact and
runtime binding.

The current 50-block Omni row now runs the intended external fixture rather than failing fixture
discovery. It reports `FAIL`: video relative L2 `0.263416433` with cosine `0.966404438`, and audio
relative L2 `0.641847052` with cosine `0.827596457`. The result is finite and executable, but not
numerically conformant. The iterative latent row cannot be promoted while its Transformer
evaluator fails and no authenticated post-repair latent oracle exists.

The recanonicalized MiniMax tree is therefore not safe to promote to main. This checkpoint is a
repair plus localization boundary, not evidence closure or a new product capability.

## Remaining limitations

- `live.minimax.omni-transformer-artifact` is a mandatory promotion failure. Its first remaining
  divergent operation after the RMS repair is not yet proven.
- `live.minimax.latent` lacks an authenticated post-repair trajectory oracle and consumes the
  currently failing Omni evaluator. It remains mandatory and unresolved.
- The late-stack run-to-run drift is a correctness signal, not an admitted stochastic model
  contract.
- `performance.runtime` remains external-asset-bound and is not required for this correctness
  integration. No new speed or memory claim is made.
- Prepared conditioning or DiT caches, decoder caches, SSD prefetch, two-slot Transformer
  streaming, and a new performance frontier remain explicitly out of scope.
- This checkpoint does not prove source-scale media quality, release readiness, or safe promotion
  of MiniMax into main.

## Why it matters

The promotion decision now rests on an authenticated numerical failure rather than absent assets:
one real source mismatch was removed, and the remaining Transformer defect has a canonical,
repeatable external oracle that prevents a corrupted vertical from entering main.
